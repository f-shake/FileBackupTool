# FileBackupTool 设计文档

一个**服务端常驻、浏览器控制**的文件备份工具。B/S 架构，公网可访问，单用户。
核心备份算法移植自 `ArchiveMaster.Module.FileBackupper`，但数据层与存储格式重新设计。

- **后端**：ASP.NET Core (.NET 10) / Kestrel / SQLite + EF Core
- **前端**：Vue 3 + TypeScript + Vite + Element Plus
- **部署**：Windows + nssm 托管为服务（开发期按双击运行设计）
- **反向代理**：nginx 终止 TLS

## 一、从 ArchiveMaster 继承了什么、推翻了什么

### 继承（算法骨架）

- **快照链模型**：`Full` / `VirtualFull` / `Increment` 三种快照，增量只记录差异。
- **镜像重建**：当前状态 = 最近一次全量快照 + 其后所有增量按 `Created` / `Modified` / `Deleted` 依次重放。
- **软删除 + 墓碑**：删除的文件在增量里留一条 `Deleted` 记录，而不是物理消失。
- **全量/增量选取策略**：固定间隔触发；距上次全量的增量数超过阈值则改跑全量。
- **虚拟全量**：只写元数据、不复制内容的快照（不可恢复）。
- **筛选规则语法**：沿用 `FzLib.IO.FileFilterRule` 的白名单/黑名单 × 文件/文件夹/路径模型。

### 推翻（重新设计）

| 原设计 | 新设计 | 原因 |
|---|---|---|
| 每任务一个 `db.sqlite`，放在备份目录里 | **集中式 SQLite**，`EnsureCreated()` → **EF migrations** | 单一迁移点、全局索引、跨任务查询 |
| blob 名 = `Guid.ToString("N")`，扁平存放 | **内容寻址** `blobs/<hash[0:2]>/<hash[2:4]>/<hash>` | 去重降级为文件系统探测；天然分片；文件名校验完整性 |
| 去重键 `(LastWriteTime, Length, SHA1)` | **内容寻址**（同名即同内容），SHA-256 | 原键含时间戳，实际不是内容去重；换内容寻址后去重率显著上升 |
| 先算哈希（读 1）→ 查重 → 再拷贝（读 2） | **`Length` 预筛**决定路径，见 [03-备份引擎](03-备份引擎.md) | 消除大文件的双读，且绝不白写 |
| `EndTime == default` 作"进行中/崩溃"隐式哨兵 | **显式 `Snapshot.Status`**（InProgress / Completed / Aborted） | 崩溃残留从"巧合"变成"状态" |
| 无索引，每次全表扫描 | 路径 / 快照 / 哈希**索引齐备**，查询走数据库端 JOIN | 十万～百万文件量级 |
| 全量物化 `List<FileInfo>` 与整链 replay 进内存 | **全程流式**，分批提交 | 百万文件会 OOM |
| 本地时间戳 | **UTC** | 跨时区/夏令时 |
| 物理删除 blob | **移入回收目录**，用户手动清理 | 软删除语义必须名副其实 |
| 无还原 API（还原逻辑长在 UI 对话框里） | **服务端还原**，白名单根目录 | 浏览器无法访问服务器文件系统 |
| 无 `CancellationToken` 参数、无 `IProgress<T>` | 公开 API 全部带 CT，进度全链路可观测 | Web 宿主的基本要求 |
| `UnauthorizedAccessException` 会炸掉整个备份 | 逐文件失败隔离 + 失败率阈值 | 见 [03-备份引擎](03-备份引擎.md) |

### 明确不继承

- **Avalonia 表现层**、`IModuleInfo` 模块系统、`AppConfig` 的 `configs.json` 存储、`FzLib.Avalonia`、静态 `NewLog` 事件、`Debug.Assert` 作数据完整性守卫、`ByWatching` 死配置（改为真正实现，见 [03-备份引擎](03-备份引擎.md)）。

## 二、决策总览

下列每一条都经过明确确认。标注"**我的默认**"的条目见 [08-测试与待定项](08-测试与待定项.md#我替你定的默认值可否决)。

### 定位与边界

| # | 决策 |
|---|---|
| 1 | **独立产品**，与 ArchiveMaster 无代码依赖；仅复用 `FzLib`（纯 .NET 部分） |
| 2 | 目标是**备份引擎常驻服务器**，浏览器只做控制面（配置 / 触发 / 看进度 / 查历史 / 还原） |
| 3 | 备份源与目标都在**服务器可见的文件系统**上（本地盘 / NAS / 共享盘） |
| 4 | **所有文件不出服务器**：不提供任何打包下载功能 |
| 5 | 单仓库：`src/`（.NET 解决方案）+ `web/`（Vite 项目），前端产物由后端带起 |
| 6 | 前端**多页面路由**形态，纯中文，自动跟随系统亮/暗色 |

### 存储

| # | 决策 |
|---|---|
| 7 | **集中式 SQLite**，一个库承载所有任务、快照、文件记录、日志 |
| 8 | **每个任务的备份目录独立，禁止共享**（含禁止互相包含） |
| 9 | blob 池 **内容寻址**，SHA-256，分片布局（见 [02](02-存储与数据模型.md)） |
| 10 | **不做**目录树/硬链接快照（用户否决：路径长度问题） |
| 11 | 备份目录内保留**抢救清单**（分片 JSON，明文，只含当前镜像） |
| 12 | 所有记录删除一律**软删除** |
| 13 | 被回收的 blob **移入 `<BackupDir>\_deleted\`**，保留分片路径，用户手动清理 |
| 14 | **不做**格式兼容：不读取 ArchiveMaster 已有的备份目录 |

### 备份引擎

| # | 决策 |
|---|---|
| 15 | 变更检测 `(LastWriteTimeUtc, Length)`；增量不重算哈希 |
| 16 | **实时备份要做**，参考 GalleryCloud 的"两套机制"，但**显式定义协作契约**（它没有） |
| 17 | 部分写入防护：`(Length, LastWriteTimeUtc)` 连续静默后才提交 |
| 18 | 触发语义：变更 → 标记脏 → 静默期 → **合并**跑一次增量 |
| 19 | **局部扫描**：只重扫变化目录，未变化目录继承上个镜像 |
| 20 | 周期性**全量扫描兜底**（兜住 watcher 静默失效） |
| 21 | UNC / 网络路径**放弃 watcher**，只跑轮询 |
| 22 | 目录重命名**不特殊处理**（表现为一次大快照） |
| 23 | 单个任务内部文件处理**串行**（机械盘） |
| 24 | **任何时刻全局最多一个后台 IO 作业**（备份或还原） |
| 25 | `WriteThrough` **去掉** |
| 26 | 三种快照类型全部保留；VirtualFull 必须显著标注"不可恢复" |

### 还原与快照

| # | 决策 |
|---|---|
| 27 | 还原到**白名单还原根目录**内，绝不接受任意路径 |
| 28 | 还原粒度：整快照 / 目录 / 多选文件 |
| 29 | 冲突策略逐文件可选，全局默认**跳过** |
| 30 | 还原**恢复原始时间戳** |
| 31 | 快照删除级联语义不变，但对话框必须**列出受影响的快照清单** |
| 32 | 保留策略手动，外加一个**可选的定时自动淘汰开关** |

### 安全

| # | 决策 |
|---|---|
| 33 | **ASP.NET Core Identity**，单用户种子 |
| 34 | **TOTP 强制开启** |
| 35 | Cookie：`HttpOnly` + `Secure` + `SameSite=Strict`，滑动 7 天 + 绝对 30 天 |
| 36 | 允许多会话，提供会话列表与单独踢出；改密失效全部会话 |
| 37 | nginx 终止 TLS；Kestrel 启用 `ForwardedHeaders`，只信任 nginx 的 IP |
| 38 | 登录限流 + 账户锁定 + 审计日志 |

### 工程

| # | 决策 |
|---|---|
| 39 | **写测试**，因此文件系统访问从第一天就抽象为接口 |
| 40 | 往返一致性测试是 **CI 硬门槛** |
| 41 | 强制单实例（全局命名 Mutex / lock file） |
| 42 | 数据目录 `App_Data`（相对应用目录），可配置 |
| 43 | 基础设施配置在 `appsettings.json`，任务定义在 DB |

## 三、架构一句话

```
浏览器 (Vue 3 SPA)
   │  REST /api  +  SignalR /hubs/events
   ▼
nginx (TLS 终止)
   ▼
Kestrel  ── ASP.NET Core (.NET 10)
   │
   ├── 全局 IO 作业队列（串行，最多 1 个作业）
   │      ├── 备份作业 ── 快照引擎 ── blob 池（内容寻址）
   │      └── 还原作业 ── 白名单还原根目录
   │
   ├── 变更监控（每个源目录一个监控器）
   │      ├── 快速路径：FileSystemWatcher（仅本地盘）
   │      └── 权威路径：扫描（周期兜底 + 局部扫描 + 启动全扫）
   │
   └── SQLite（集中式，EF Core migrations）
```

## 四、关键风险与对策

| 风险 | 对策 |
|---|---|
| **任意路径写入 = 服务器沦陷**（还原是写文件操作） | 还原目标限制在白名单还原根目录内；公网部署强制 TOTP |
| **watcher 静默失效导致永久漏备份** | 三个显式钩子 + 周期性全量扫描兜底（见 [03](03-备份引擎.md)） |
| **部分写入的文件被固化成坏 blob 并反复复用** | 静默期冻结 + `IOException` 退避重试（见 [03](03-备份引擎.md)） |
| **"显示成功但备份不完整"** | 快照携带失败计数，UI 明确显示"完成，但 N 个文件未备份" |
| **百万文件下 OOM** | 全程流式 + 分批提交 + 局部扫描 |
| **nssm 下误起两个实例 → 静默毁数据** | 全局命名 Mutex 强制单实例 |
| **备份目录落在源目录内 → 自我触发死循环** | 保存任务时校验目录关系（见 [03](03-备份引擎.md)） |
