# 07 · 前端设计

## 1. 技术选型

| 项 | 选型 |
|---|---|
| 框架 | Vue 3 + TypeScript |
| 构建 | Vite |
| UI 库 | Element Plus（中文） |
| 状态 | Pinia |
| 路由 | Vue Router（多页面形态） |
| 实时 | SignalR (`@microsoft/signalr`) |
| 主题 | Element Plus 亮/暗色，**自动跟随系统**（`prefers-color-scheme`），允许手动覆盖 |

**语言**：纯中文。**不引入 i18n 框架**——避免过度设计，文案集中在一个 `locales/zh-CN.ts` 以便将来抽取。

## 2. 信息架构

多页面路由形态：

| 路由 | 页面 | 说明 |
|---|---|---|
| `/` | 重定向到 `/tasks` | |
| `/tasks` | **任务列表** | 每个任务一张卡片：名称、状态、上次备份时间、上次结果（含失败计数）、源/目标、下次计划时间、监控状态。操作：立即备份、取消、启用/禁用、编辑、删除 |
| `/tasks/:id` | **任务详情** | 头部：任务名 + 快捷操作（立即备份 / 取消 / 刷新）。内部 Tab：`概览` / `快照` / `日志` / `监控` |
| `/tasks/:id/snapshots/:sid` | **快照文件浏览** | **独立路由**（不是 Tab），便于直接发链接与浏览器前进后退。这是使用频率最高的页面 |
| `/tasks/:id/logs` | **任务日志** | 独立路由，便于从别处跳转并带筛选参数 |
| `/monitor` | **全局实时监控** | 所有任务的监控状态、待处理变更队列、作业队列、最近触发记录 |
| `/settings` | **设置** | 通用（数据目录、日志）+ 安全（密码、TOTP、恢复码、会话列表）+ 还原根白名单 + 保留策略 |
| `/settings/audit` | **审计日志** | |
| `/login` | 登录 | 含 TOTP 步骤与首次绑定流程 |

**为什么把"快照文件浏览"做成独立路由**：它是使用频率最高的页面，值得有自己的 URL。其余页面内部的 Tab 不占路由。

## 3. 相对旧界面的补齐清单

**底线是"≥ 现有 ArchiveMaster 提供的能力"**（完整的对等清单见 §5）。在满足对等的前提下，明确补齐以下 **7 项**——它们都是现有实现里公认的短板，且成本低：

| # | 补齐项 | 现状 |
|---|---|---|
| 1 | 快照列表加**占用空间列** + 类型/日期筛选 + 分页 | 旧界面只有文件计数，无大小、无筛选、无分页 |
| 2 | 日志的时间范围改用**日期选择器** | 旧界面是两个裸文本框绑 `DateTime`，无格式提示 |
| 3 | 文件树搜索改为**真过滤** | 旧界面是"展开整棵树 + 多选匹配项"，不是过滤 |
| 4 | **多选**（复选框列） | 旧界面所有网格都是单选；复选框机制写好了但被禁用 |
| 5 | **右键菜单** | 旧界面只有 `复制信息` 下拉，没有右键菜单 |
| 6 | 还原/另存遇到目标已存在时**不再静默覆盖** | 旧界面用 `FileMode.Create`，静默覆盖 |
| 7 | **备份进度条** | 旧界面备份时**完全没有进度条**，只是锁住面板 + 滚"最后的日志" |

> 第 4 项的实现可以参考旧项目里 `TreeDirInfo` 的**三态勾选传播算法**（父/子/半选状态联动）——那是现成的参考实现。

## 4. 页面详述

### 4.1 任务列表 `/tasks`

卡片式而非表格——因为要展示的信息（状态、进度、监控模式、下次计划）比表格列更丰富。

每张卡片：

- 任务名 + 启用开关
- 状态徽章：`就绪` / `正在全量备份` / `正在增量备份` / `错误` / `已排队`
- 上次备份时间 + 结果：`成功` / `成功（N 个文件失败）` / `已中止`——**失败计数必须显眼**
- 源目录 / 备份目录（长路径省略中段，hover 显示全路径）
- 监控模式徽章：`实时监控` / `轮询模式`（UNC/NAS 源）
- 下次计划备份时间
- 正在运行时：进度条（走 SignalR）
- 操作：立即备份（全量/虚拟全量/增量 下拉）、取消、编辑、删除

**任务编辑表单**字段（对齐旧界面并修正）：

| 字段 | 控件 | 说明 |
|---|---|---|
| 任务名 | 输入框 | |
| 需要备份的目录 | 目录选择器 | 支持手输 + 服务端目录浏览 + 拖放 |
| 备份文件存放目录 | 目录选择器 | **实时校验与其它任务/源目录的关系** |
| 启用 | 开关 | **新增**（旧设计没有任务级启用开关，只能靠两个子开关间接控制） |
| 定时备份 | 开关 + **分钟数输入** | **修正**：旧界面用的是 TimePicker（选时刻），语义错误 |
| 增量备份最大数量 | 数字输入 | 说明文案：`当一个连续的增量备份超过该数量后，将进行一次全量备份` |
| 自动全量时使用虚拟全量 | 开关 | |
| 变更监控 | 开关 | 说明：旧的 `ByWatching` 是**死配置**，新设计真正实现 |
| 筛选规则 | 可视化编辑器 | 白名单/黑名单 × 文件/文件夹/路径，可切正则，带「使用当前目录测试」 |

**筛选规则编辑器**沿用旧的语义与说明文案（`每一组文本框中，可以输入多行匹配条件，任意一条匹配成功则认为该组匹配成功…`），但改造成 Web 组件，并保留「使用当前目录测试」→ 返回文件数量与文件大小。

### 4.2 快照文件浏览 `/tasks/:id/snapshots/:sid`

**核心页面。** 三栏布局：

```
┌──────────────┬─────────────────────────────────┬──────────────┐
│ 快照导航      │ 文件浏览器                        │ 详情面板      │
│ (全量分组树)  │ (路径面包屑 + 搜索 + 表格)          │ (选中文件)    │
│              │                                 │              │
│ 全量 09-22    │ 名称 │大小│修改时间│哈希│操作       │ 完整路径      │
│  ├ 增量 …     │ 📁 报告                              │ 大小 / 时间   │
│  ├ 增量 …     │ 📄 a.docx  12KB …                    │ 哈希          │
│ 全量 09-20    │ 📄 b.xlsx  8KB  …                    │ 所属快照      │
│  └ 增量 …     │                                 │ 版本历史      │
└──────────────┴─────────────────────────────────┴──────────────┘
```

- **左侧**：快照按全量分组的时间轴导航，可切换快照。
- **中间**：当前目录的表格视图（**服务端分页**，因为可能有百万文件）。
  - 列：`名称`（带文件夹/文件图标）/ `文件大小`（目录显示 `{D}个子文件夹，{F}个子文件`）/ `修改时间` / `哈希` / `操作`。
  - **注意**：旧界面的 `备份文件名` 与 `文件哈希（SHA1）` 两列**合并为一列**——内容寻址后 blob 名就是哈希。
  - 顶部面包屑 + 搜索框（**真过滤**）+ 多选复选框 + 右键菜单。
  - 点击行 → 右侧详情面板。
- **右侧**：选中文件的元数据 + `版本历史`（该路径的所有版本，可选中任一版本还原）。

**只显示文件名与元数据，不做内容预览。**（用户明确要求）

**已删除的文件**：镜像里**不显示**（镜像 = 该快照的物化状态）。要看"这个快照删了什么"用「变更内容」。

### 4.3 变更内容

三列并排：`新增的文件` / `修改的文件` / `删除的文件`。

列：`文件名` / `路径` / `文件大小` / `修改时间` / `信息`。带 `共 N 项` 尾部统计。

### 4.4 任务日志

- 类型筛选下拉：`细节` / `调试` / `信息` / `警告` / `错误` / `关键` / `全部`（沿用旧文案映射）
- **日期时间范围选择器**（补齐项 2）
- `关键词搜索`（匹配 `Message`）
- 分页（**固定每页 100**——旧实现是 DEBUG 下 10、Release 下 100，构建相关，不可接受）
- 列：`类型` / `时间` / `信息` / `操作-详情`（有 `Detail` 时显示）
- **实时追加**：订阅 `log.appended`，可开关"跟随"（旧界面完全没有自动刷新）
- **级别着色**（旧界面无着色）

### 4.5 还原

向导式，**先预演后执行**：

1. **选范围**：整快照 / 目录 / 多选文件
2. **选目标**：从白名单还原根目录中选择（不接受任意路径）
3. **预演**：调 `/api/restore/plan` → 显示将写入的文件数、总大小、**冲突明细**（哪些文件目标已存在）
4. **定策略**：冲突策略（跳过/覆盖/保留两者/较新者优先），可"应用到全部"，可逐条覆盖
5. **执行**：入队 → 进度 → 结果汇总（成功/跳过/失败 + 失败清单）

### 4.6 全局监控 `/monitor`

- 每个任务/源的监控状态：`实时监控` / `轮询模式` / `监控异常`
- 待处理变更队列长度与内容（哪些目录脏了、
 静默期倒计时）
- 全局作业队列：运行中 / 排队中（含排队位置）
- 最近触发记录

**旧界面完全没有这个页面**——而它恰好是"备份到底有没有在工作"最需要可见的地方。

## 6. 实时通信

**SignalR 为主通道，REST 轮询为降级方案。**

- 连接 `/hubs/events`，订阅 `task:{taskId}` 分组。
- 断线自动重连（SignalR 内置），重连后调 REST 拉一次全量快照状态（**不能用增量事件补齐**，因为断线期间的事件已经丢了）。
- 若 SignalR 完全不可用（代理配置错误、WebSocket 被阻断），自动降级为**每 5 秒轮询**。UI 上显示当前通道（`实时` / `轮询`）。

> 旧界面完全没有实时推送；GalleryCloud 是 5 秒轮询，README 里把 WebSocket 列为待办。这里直接做到位。

## 7. 交互约定

- **破坏性操作一律二次确认**，并列出影响范围：删除快照（列级联清单）、清空回收站（不可逆）、删除任务。
- **长任务一律有进度、可取消**（备份、还原、校验、回收、清单生成、删除快照）。
- **"成功但不完整"必须醒目**：快照的失败计数、丢失的 blob、跳过的文件，都要用非绿色的提示呈现。
- **长路径显示**：中段省略 + hover 显示全路径（路径很容易超过容器宽度）。
- **中文日期时间格式**统一 `yyyy-MM-dd HH:mm:ss`，时区显示为本地。
